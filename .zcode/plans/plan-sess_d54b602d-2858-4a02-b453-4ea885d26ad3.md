# A.T.L.A.S — Phase 1 Completion + Phase 2 Enterprise IaC

- **Scope**: Finish Phase 1 (installer + backup + scripts + docs), then Phase 2 (enterprise IaC). Phase 3 (GitHub Actions, Vault, SBOM, Trivy, cosign, mTLS, Watchtower) is **out of scope** this session.

## Part A — Phase 1 Completion (4 workstreams)

### A1. Cross-platform installer
**New files at repo root + `installer/lib/`:**

| File | Purpose |
|------|---------|
| `install` | POSIX entrypoint (bash). Sources `installer/lib/*.sh`, calls `bootstrap`. chmod +x. |
| `install.bat` | Windows entrypoint. Sources `installer/lib/*.ps1`, calls `bootstrap`. |
| `installer/README.md` | How the installer works, prerequisites, re-run semantics. |
| `installer/lib/detect.sh` + `detect.ps1` | Detect OS, arch (x64/arm64), RAM, GPU (`nvidia-smi` / `system_profiler` / `wmic`), Docker presence+version, disk space. Emits a spec report. |
| `installer/lib/docker_install.sh` + `docker_install.ps1` | Idempotent Docker install: Linux via `get.docker.com` + usermod; Mac via `brew install --cask docker`; Windows via `winget Docker.DockerDesktop` (with the documented "user must start Docker Desktop once" caveat). |
| `installer/lib/secrets.py` | Generates `~/.atlas/.env` with `secrets.token_urlsafe()` for `POSTGRES_PASSWORD`, `NEO4J_PASSWORD`, `JWT_SECRET`, `JWT_REFRESH_SECRET`, `MINIO_ACCESS_KEY`/`SECRET_KEY`, `ATLAS_API_KEY`, `ATLAS_BACKUP_KEY` (32-byte AES key). **Never overwrites** an existing file unless `--force`. Optionally merges in user-supplied LLM keys (`OPENAI_API_KEY` etc.) via prompts or `--env-file`. |
| `installer/lib/bootstrap.sh` + `bootstrap.ps1` | Orchestrates: detect → docker_install → secrets → symlink `.env` → `docker compose build` → `docker compose up -d` → healthcheck → open app. Idempotent and re-runnable. |
| `installer/lib/healthcheck.py` | Polls `http://localhost/readyz` + per-DB healthchecks with timeout/progress. Exits non-zero with a diagnostic hint on failure (points at `scripts/doctor.py`). |

**Symlinks `.env`**: installer writes `~/.atlas/.env` then copies/symlinks it into the repo root so `docker compose` picks it up automatically. The existing hardened `.gitignore` already covers `.env*`.

### A2. Backup automation
**New files in `infrastructure/backup/`** (the `Dockerfile` here is already referenced by `docker-compose.yml`'s `atlas-backup` service but doesn't exist — this closes that gap):

| File | Purpose |
|------|---------|
| `Dockerfile` | Python 3.12-slim, installs `postgresql-client`, `redis-tools`, `neo4j` admin tools, `cryptography`, `minio`. Cron-style entrypoint. |
| `backup.py` | Dumps: `pg_dump`, `redis-cli --rdb`, `neo4j-admin database dump`, Qdrant snapshot API. Tar everything, encrypt with AES-256-GCM (`ATLAS_BACKUP_KEY`), upload to MinIO bucket `atlas-backups` with timestamped object name. Prunes to `ATLAS_BACKUP_RETENTION` (default 14). |
| `restore.py` | Takes `<name>` or `latest`. Downloads from MinIO, decrypts, restores per-DB. **Refuses non-empty targets without `--force`**. |
| `entrypoint.sh` | Cron loop on `ATLAS_BACKUP_SCHEDULE` (default `0 2 * * *`). Runs `backup.py` then sleeps. Also exposes `restore` as a one-shot mode via `ATLAS_MODE=restore`. |
| `requirements.txt` | `minio`, `cryptography`, `psycopg2-binary`, `qdrant-client`, `neo4j`. |

Wired into compose via the existing `backup` profile: `docker compose --profile backup up -d`.

### A3. Helper scripts
**New files in `scripts/`:**

| File | Purpose |
|------|---------|
| `generate_env.py` | Standalone version of `installer/lib/secrets.py` — generates a `.env` in the current dir without running the full bootstrap. Useful for devs who already have Docker. Flags: `--output`, `--force`, `--with-llm-keys`. |
| `doctor.py` | Diagnostics CLI. Checks: Docker daemon running, ports 80/443/3000/8000 free, `.env` exists and has all required keys, each compose service healthcheck status, common failure hints (Docker Desktop not started, wrong compose file, missing `.env`). Prints a traffic-light report. |

### A4. Documentation
**New files in `docs/`:**

| `operations.md` | Backups (`docker compose --profile backup`, `restore.py latest`), logs (`docker compose logs`, Loki), scaling (replicas in prod compose), GPU enablement (`ATLAS_ENABLE_GPU=1`), update flow. |

Also: light touch on root `README.md` to point at `./install` and the new docs.

**Phase 1 definition of done**: installer runs end-to-end on paper (all scripts present and internally consistent), backup Dockerfile that compose references now exists, `docker compose config` validates the base + dev + prod files, all new Python passes `py_compile`.

## Part B — Phase 2 Enterprise IaC (6 workstreams)

### B1. `docker-compose.enterprise.yml`
Enterprise overlay on top of base compose. Adds vs `prod`:
- Multiple backend replicas behind Traefik with sticky sessions
- External secrets via file-based Docker Secrets (`/run/secrets/*`) for DB passwords, JWT keys — `/run/secrets/*` mounted read-only, app reads via a thin shim
- Stricter resource limits + CPU reservations
- Vault Agent sidecar reference (documented; actual Vault is Phase 3)
- Watchtower service (opt-in `updates` profile) for automatic image refresh from GHCR
- Image pull policy `always`, `ATLAS_IMAGE_TAG` env var to pin versions
- Dedicated `atlas-enterprise` network with internal-only DB subnet enforcement

## Validation pass (at the end, static only)
- `docker compose -f infrastructure/docker/docker-compose.yml config` (+ dev/prod/enterprise layered)
- `python -m py_compile` on all new `.py` files (installer libs, backup, scripts)
- `yamllint` or Python `yaml.safe_load` on every new YAML (compose, k8s, helm values, ansible vars)
- `terraform fmt -check -recursive` + `terraform -chdir=... init -backend=false && validate` if Terraform CLI is present; otherwise YAML/HCL parse only
- `helm lint infrastructure/helm/atlas` if Helm CLI present
- `ansible-playbook --syntax-check` on each playbook if Ansible CLI present
- Bash `shellcheck` on installer `.sh` files if present
