# A.T.L.A.S — Phase 1 Plan: Local Docker Dev Stack + Installer

## Scope Summary

**Goal:** After running ONE command (`./install` / `install.bat`), the entire ATLAS stack comes up on any OS with zero manual setup — Docker is detected/installed, secrets generated, images pulled, services started, health-checked, and the desktop app opens.

**In scope (Phase 1):**
- Dockerfiles + docker-compose (lean core + opt-in profiles)
- Cross-platform installer (Win/Mac/Linux) with full bootstrap
- JWT auth scaffold + secure secret generation
- Working backup job + restore (Postgres/Neo4j/Redis/Qdrant → MinIO)
- Backend minimal fixes to run cleanly in containers
- Frontend rebuild to TS + Tailwind + shadcn/ui **+ Tauri desktop shell**
- AWS + Azure Terraform stubs (foundational; full modules deferred)
- `.gitignore` hardening so secrets never commit

**Explicitly deferred to later phases** (called out so expectations are clear):
- Production K8s manifests, full Helm chart, HPA, NetworkPolicies (Phase 2)
- Full Terraform modules (VPC/EKS/AKS/RDS/ACR/ALB/DNS) (Phase 2)
- Ansible playbooks (Phase 2)
- GitHub Actions CI/CD, SBOM, image signing, Vault (Phase 3)
- Kafka, full OIDC/OAuth2/RBAC/mTLS, rootless containers, network segmentation hardening (Phase 3+)
- Wiring LLM adapters into the orchestrator, real agent logic (Phase 4 — app logic)
- Mobile client

> Note on Next.js version: spec says "Next.js 16." As of July 2026 the latest stable is Next 15.x; I'll use the latest stable release. If 16 is GA by the time of execution, I'll use it.

## Workstreams (in execution order)

### WS-1: Project hygiene & manifests
- Write `requirements.txt` (fastapi, uvicorn, psycopg2-binary, redis, qdrant-client, neo4j, python-jose, passlib, pydantic-settings, prometheus-client, opentelemetry-sdk, minio, faster-whisper, playwright, langgraph, langchain, openai, anthropic, google-generativeai — pinned).
- Write `pyproject.toml` (ruff/black config).
- Harden `.gitignore` (`.env*`, `.next/`, `node_modules/`, `screenshots/`, `*.wav`, `__pycache__/`, `terraform.tfstate*`, MinIO data, backup artifacts).
- Move hardcoded secrets out of compose into `${VAR}` with `.env` defaults.

### WS-2: Backend Dockerfile + minimal fixes
**Dockerfile.backend** (multi-stage, slim): python:3.12-slim base, install system deps (libpq, curl, Chromium deps for Playwright), `pip install -r requirements.txt`, `playwright install chromium`, non-root user, `HEALTHCHECK CMD curl /healthz`.

**Minimal fixes to `server.py`** (NOT feature changes):
- Fix the `status["postgres"] = True` copy-paste in the Redis check (line 96).
- Fix the broken `workflows/task_scheduler.py` import path (`orchestrator-agent` → can't be imported as dotted module; convert to a `sys.path`-based import consistent with the existing pattern in server.py).
- Add `/healthz` (liveness) and `/readyz` (DB-readiness) endpoints.
- Add `/metrics` (Prometheus exposition).
- Tighten CORS to read allowed origins from env (default localhost:3000 + tauri://).

### WS-3: JWT auth scaffold (new `services/auth/`)
- `User` model in Postgres init (id, email, password_hash, role, created_at).
- `services/auth/jwt.py`: HS256 access (15m) + refresh (7d) tokens, secret from env.
- `services/auth/middleware.py`: FastAPI dependency that protects routes via `Authorization: Bearer`.
- `services/auth/routes.py`: `/auth/signup`, `/auth/login`, `/auth/refresh` (passlib bcrypt).
- WebSocket `/ws` accepts token via query string `?token=`.
- DB init SQL for `users` + `refresh_tokens` (with rotation tracking).

### WS-4: Docker Compose rewrite (lean core + profiles)
**Default `docker compose up` brings up (lean core):**
- `postgres`, `redis`, `neo4j`, `qdrant` (with healthchecks, init volumes mounted from `infrastructure/init/`)
- `atlas-backend` (builds Dockerfile.backend, depends_on healthy DBs, env from `.env`)
- `atlas-frontend` (builds desktop-client Dockerfile, Next.js standalone output)
- `traefik` (single entry on :80/:443, routes atlas.localhost → frontend, api.atlas.localhost → backend)
- `minio` (S3-compatible object store for backups)

**Profiles (opt-in):**
- `--profile observability` → prometheus, grafana, loki, promtail, cadvisor, node-exporter, otel-collector
- `--profile messaging` → kafka + zookeeper (or redpanda)
- `--profile gpu` → applies GPU device reservations to backend (only honored when host has toolkit)

**Cross-cutting on every service:** healthcheck, resource limits (`deploy.resources`), restart policy, structured logging (json-file with size caps), connected to the correct network.

**Networks:** `atlas-frontend`, `atlas-backend`, `atlas-database`, `atlas-monitoring`, `atlas-management` — only Traefik publishes host ports.

**Compose variants:**
- `docker-compose.yml` — base
- `docker-compose.dev.yml` — hot reload (volume mounts, debug logging, no resource limits)
- `docker-compose.prod.yml` — restart=always, tighter limits, external Traefik TLS
- `docker-compose.observability.yml` — pulled in by profile

### WS-5: Traefik config
- `traefik.yml`: entrypoints :80/:443, dashboard disabled in prod, ACME optional.
- `dynamic/tls.yml`: TLS options, HSTS.
- `dynamic/auth.yml`: forward-auth to backend's `/auth/verify` for protected routes.
- `dynamic/ratelimit.yml`: per-IP burst limiting on API.

### WS-6: Frontend rebuild (`apps/desktop-client/`)
- Wipe `.next/` cache (gitignored anyway).
- Re-init as Next.js + TypeScript + TailwindCSS + shadcn/ui.
- Port the existing Control Deck UI/features: DB health indicators, latency/load telemetry, agent node inspector, WebSocket thought-stream terminal, hologram voice receptor, `webkitSpeechRecognition` wake phrase, command input.
- Preserve all WebSocket message shapes (`telemetry`, `log`) so no backend change needed.
- Use shadcn primitives (Card, Badge, Button, Input, ScrollArea, Tabs) for the visual refresh.
- **Dockerfile** (multi-stage): node:20 → `next build` (standalone output) → minimal runtime image.
- Add `/auth/login` + `/auth/signup` pages wired to the new JWT endpoints; store token in httpOnly cookie + localStorage for WS.

### WS-7: Tauri desktop shell (`apps/desktop/`)
- New `apps/desktop/src-tauri/` with `tauri.conf.json` pointing `devUrl`/`frontendDist` at the built Next.js app.
- Tauri window: 1440x900, custom titlebar matching the cyber theme.
- **First-run logic in Rust**: check for `~/.atlas/.env`; if missing, spawn the installer bootstrap (WS-9) and show a progress overlay; otherwise load the dashboard.
- **Auto-updater**: Tauri's built-in updater pointed at GitHub Releases (key set in later phase).
- Build native installers (.msi/.dmg/.deb/.AppImage) via `tauri build`.
- README documents how to build per-OS.

### WS-8: Init scripts (databases)
- `postgres/001_init.sql`: `users`, `refresh_tokens`, `session_messages`, indexes, extensions (`pgcrypto`).
- `neo4j/constraints.cypher`: uniqueness constraints on User nodes.
- `qdrant/collections.json`: create `atlas_memory` collection (cosine, 1536 dims) on startup.
- Mounted read-only into the DB containers via compose.

### WS-9: Cross-platform installer (`install`, `install.bat`, `installer/lib/*`)
**Flow** (idempotent — safe to re-run):
1. **Detect**: OS, arch (x64/arm64), total RAM, GPU (NVIDIA via `nvidia-smi` / `system_profiler` / `wmic`), Docker presence+version, disk space.
2. **Docker**: if missing or too old, install via official channel:
   - Win: winget `Docker.DockerDesktop` → prompt user to start it (Docker Desktop can't be fully silent)
   - Mac: Homebrew `--cask docker` (install brew if missing)
   - Linux: `get.docker.com` script + add user to docker group
3. **Secrets**: run `installer/lib/secrets.py` → write `~/.atlas/.env` with cryptographically random POSTGRES_PASSWORD, NEO4J_PASSWORD, JWT_SECRET, JWT_REFRESH_SECRET, MINIO keys, ATLAS_API_KEY. Never overwrite existing secrets.
4. **Compose env**: symlink/copy `~/.atlas/.env` to project `.env`.
5. **Pull + build**: `docker compose build && docker compose pull`.
6. **Bring up**: `docker compose up -d`.
7. **Healthcheck**: poll `http://localhost/readyz` + per-DB checks; show progress bars.
8. **GPU report**: log detected GPU + tell user how to enable (`ATLAS_ENABLE_GPU=1` + `--profile gpu`).
9. **Open app**: launch Tauri binary if built, else open `http://atlas.localhost` in default browser.
10. Print summary: detected specs, what was installed, where `.env` lives, how to stop/start.

**`scripts/doctor.py`** — standalone diagnostics that prints why startup failed (port conflicts, Docker not running, unhealthy service, bad secret).

### WS-10: Backup automation (`infrastructure/backup/`)
- **`backup.py`**: per-DB dump (pg_dump, `redis-cli --rdb`, neo4j admin dump, qdrant snapshot API), tar+encrypt with AES-256-GCM (key from `ATLAS_BACKUP_KEY`), upload to MinIO bucket `atlas-backups` with timestamped object name.
- **`restore.py`**: takes a backup name (or `latest`), downloads, decrypts, restores per-DB. Refuses to restore into a non-empty DB without `--force`.
- **`entrypoint.sh`**: lightweight cron loop (default nightly 02:00, configurable via `ATLAS_BACKUP_SCHEDULE`).
- **Retention**: keep last N (default 14), prune older in MinIO.
- Packaged as its own Docker image, wired into compose with the `backup` profile.

### WS-11: Terraform foundational stubs (AWS + Azure)
- Modular layout: `terraform/aws/` and `terraform/azure/` each with `versions.tf`, `providers.tf`, `variables.tf`, `main.tf`, `outputs.tf`, `backend.tf.example`.
- **Foundational only**: provider config, remote state (S3+DynamoDB / Azure Storage), a resource group, and a tagged placeholder. **Real VPC/EKS/AKS/managed-DB modules are Phase 2** — clearly marked with TODOs so Phase 2 is a fill-in exercise, not a rewrite.
- Document `terraform init/plan/apply` workflow.

### WS-12: Documentation
- `docs/deployment.md`: install + compose up/down + profiles + troubleshooting.
- `docs/operations.md`: backups, restores, logs, scaling, GPU enablement.
- Update root `README.md` with the new install flow and link to docs.

## Validation criteria for Phase 1 (definition of done)

On a clean Win/Mac/Linux machine with no Docker:
1. `./install` (or `install.bat`) detects the OS/arch/GPU, installs Docker, generates secrets, builds and pulls images, brings up the stack, passes healthchecks, and opens the app — with no manual commands.
2. `docker compose up` from the repo brings up the lean core in <2 min; `docker compose --profile observability up` adds the monitoring stack.
3. Signup → login → authenticated WebSocket works end-to-end with real JWT tokens.
4. Triggering a backup produces an encrypted object in MinIO; `restore.py latest` restores it.
5. Stopping and re-running `./install` is idempotent (no secret rotation, no rebuild unless code changed).
6. Tauri binary launches the dashboard as a desktop window and re-runs the bootstrap if `~/.atlas/.env` is absent.
7. `git status` shows no committed secrets (`.env`, `*.tfstate`, etc.).

## Risk callouts

- **"Both 2 and 3" frontend + Tauri shell is the largest workstream** (~40% of Phase 1 effort). If time-boxed, the Tauri shell (WS-7) is the natural candidate to defer — the web app remains fully functional and the installer just opens a browser tab. I'll proceed with both but flag if it's worth splitting.
- **Docker Desktop on Windows can't be silently installed** — the installer will install it and prompt the user to start Docker Desktop and re-run. This is the one unavoidable manual step on Windows and I'll document it clearly.
- **Tauri build requires Rust toolchain + per-OS native build** for the installers; the script installer (WS-9) works everywhere regardless, so Tauri is the "nice to have" layer on top.
