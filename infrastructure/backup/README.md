# A.T.L.A.S Backup & Restore

Encrypted, scheduled, retention-managed backups of all ATLAS stateful
datastores, pushed to MinIO.

## What gets backed up

| Datastore   | Tool                          | Artifact         |
|-------------|-------------------------------|------------------|
| PostgreSQL  | `pg_dump` (custom format)     | `postgres.dump`  |
| Redis       | `redis-cli --rdb`             | `redis.rdb`      |
| Neo4j       | `neo4j-admin database dump`   | `neo4j.dump`     |
| Qdrant      | snapshot API (per collection) | `qdrant/*.snapshot` |

All four are tarred into one bundle, encrypted with **AES-256-GCM** using
`ATLAS_BACKUP_KEY`, and uploaded to MinIO object `atlas-backup-<UTC>.tar.gz.enc`.

Old backups are pruned to `ATLAS_BACKUP_RETENTION` (default 14).

---

## Running

The backup job is wired into `docker-compose.yml` under the `backup` profile:

```bash
# Start the scheduled backup job (default: nightly 02:00 UTC)
docker compose --profile backup up -d atlas-backup

# Run a one-shot backup now (exits when done)
docker compose --profile backup run --rm \
    -e ATLAS_MODE=backup atlas-backup

# Restore the latest backup (interactive — refuses non-empty targets)
docker compose --profile backup run --rm \
    -e ATLAS_MODE=restore -e ATLAS_RESTORE_ARGS="latest --force" atlas-backup
```

All commands assume you are in `infrastructure/docker/` and that `.env` has been
generated by the installer.

## Environment variables

| Variable                 | Default         | Description                                |
|--------------------------|-----------------|--------------------------------------------|
| `ATLAS_MODE`             | `schedule`      | `schedule` / `backup` / `restore`          |
| `ATLAS_BACKUP_SCHEDULE`  | `0 2 * * *`     | Cron: minute hour dom month dow (UTC)      |
| `ATLAS_BACKUP_RETENTION` | `14`            | Keep last N backups                        |
| `ATLAS_BACKUP_KEY`       | *required*      | Base64 32-byte AES-256-GCM key             |
| `MINIO_ENDPOINT`         | `minio:9000`    |                                            |
| `MINIO_ACCESS_KEY`       | *required*      |                                            |
| `MINIO_SECRET_KEY`       | *required*      |                                            |
| `MINIO_BUCKET`           | `atlas-backups` |                                            |
| `MINIO_SECURE`           | `false`         |                                            |

DB connection vars (`POSTGRES_*`, `REDIS_*`, `NEO4J_*`, `QDRANT_*`) are the
same ones the backend uses.

## Manual restore (outside Docker)

```bash
# From the project root, with a current venv that has backup/requirements.txt installed:
python infrastructure/backup/restore.py latest            # interactive
python infrastructure/backup/restore.py latest --force    # destructive
python infrastructure/backup/restore.py latest --only postgres redis
python infrastructure/backup/restore.py atlas-backup-20260101T020000Z.tar.gz.enc
```

`restore.py` resolves `latest` to the most recent object, `--only` to filter
datastores, and a substring to a specific named backup.

---

## Rotating the encryption key

1. Generate a new key: `python -c "import secrets;print(secrets.token_urlsafe(32))"`
2. Update `ATLAS_BACKUP_KEY` in `~/.atlas/.env` (and the repo `.env`).
3. Run one fresh backup — **old backups can no longer be decrypted** by the new key.
   Keep the old key somewhere safe if you may need to restore from before the rotation.

---

## Disaster recovery

In the worst case (lost host + lost `.env`):

1. Reinstall ATLAS: `./install` (generates new secrets but DBs are empty).
2. Recover `ATLAS_BACKUP_KEY` from your off-host secret store (password manager, Vault).
3. `docker compose --profile backup run --rm -e ATLAS_MODE=restore -e ATLAS_RESTORE_ARGS="latest --force" atlas-backup`

Backups are encrypted at rest in MinIO, so even a compromised MinIO does not leak data without the key.
